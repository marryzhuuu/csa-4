## Язык программирования JavaLight (JL)

### 1. Синтаксис

Расширенная форма Бэкуса-Наура:

```ebnf
<program>     ::= { <decl> }

<decl>        ::= <var_decl> | <fn_decl>

<var_decl>    ::= "var"   <ident> ":" <type> [ "=" <expr> ] ";"
               |  "const" <ident> ":" <type>   "=" <expr>   ";"

<fn_decl>     ::= "fn" <ident> "(" [ <param_list> ] ")" [ ":" <type> ] <block>

<param_list>  ::= <param> { "," <param> }
<param>       ::= <ident> ":" <type>

<type>        ::= "int" | "bool" | "str" | "void"

<block>       ::= "{" { <stmt> } "}"

<stmt>        ::= <var_decl>
               | <assign_stmt>
               | <if_stmt>
               | <while_stmt>
               | <for_stmt>
               | <return_stmt>
               | <break_stmt>
               | <continue_stmt>
               | <expr_stmt>
               | <block>

<assign_stmt> ::= <ident> "=" <expr> ";"

<if_stmt>     ::= "if" "(" <expr> ")" <block> [ "else" ( <if_stmt> | <block> ) ]
<while_stmt>  ::= "while" "(" <expr> ")" <block>
<for_stmt>    ::= "for" "(" ( <var_decl> | <assign_stmt> | ";" )
                            <expr> ";"
                            ( <assign_stmt_no_semi> | <expr> ) ")" <block>

<return_stmt>  ::= "return" [ <expr> ] ";"
<break_stmt>   ::= "break" ";"
<continue_stmt>::= "continue" ";"
<expr_stmt>    ::= <expr> ";"

<expr>        ::= <assign_expr>
<assign_expr> ::= <or_expr> | <ident> "=" <assign_expr>
<or_expr>     ::= <and_expr>  { "||" <and_expr>  }
<and_expr>    ::= <eq_expr>   { "&&" <eq_expr>   }
<eq_expr>     ::= <rel_expr>  { ( "==" | "!=" ) <rel_expr> }
<rel_expr>    ::= <add_expr>  { ( "<" | "<=" | ">" | ">=" ) <add_expr> }
<add_expr>    ::= <mul_expr>  { ( "+" | "-" ) <mul_expr> }
<mul_expr>    ::= <unary_expr> { ( "*" | "/" | "%" ) <unary_expr> }
<unary_expr>  ::= ( "!" | "-" ) <unary_expr> | <primary_expr>
<primary_expr>::= <literal> | <ident> | "(" <expr> ")" | <ident> "(" [ <arg_list> ] ")"
<arg_list>    ::= <expr> { "," <expr> }

<literal>     ::= <int_lit> | <bool_lit> | <string_lit>
<int_lit>     ::= [ "-" ] DIGIT { DIGIT }
<bool_lit>    ::= "true" | "false"
<string_lit>  ::= '"' { <str_char> } '"'
<str_char>    ::= любой символ кроме '"' и '\n' | "\" ( "n" | "t" | "\" | '"' )

<ident>       ::= LETTER { LETTER | DIGIT | "_" }
LETTER        ::= [a-z] | [A-Z] | "_"
DIGIT         ::= [0-9]
```

### 2. Семантика языка

#### 2.1 Стратегия вычислений

**Строгая**: каждое выражение вычисляется полностью до передачи значения. Аргументы функции вычисляются слева направо до вызова. **Исключение** — логические `&&` и `||` с ленивым вычислением:

```
false && side_effect()   // side_effect() не вызывается
true  || side_effect()   // side_effect() не вызывается
```

#### 2.2 Области видимости

**Статическая (лексическая)** область видимости. Три уровня:

- **Глобальный** — объявления `fn` на верхнем уровне файла. Все имена видны с начала файла (взаимная рекурсия работает).
- **Функции** — параметры и локальные переменные тела.
- **Блока** — переменная, объявленная в `{ }`, видна только внутри.

Внутренняя переменная с тем же именем затеняет внешнюю; внешняя снова видна после `}`.

#### 2.3 Типизация

**Статическая явная**. Четыре встроенных типа:

| Тип    | Размер       | Диапазон / представление                   | Назначение              |
|--------|--------------|--------------------------------------------|-------------------------|
| `int`  | 32 бита      | −2 147 483 648 … 2 147 483 647             | целые со знаком         |
| `bool` | 32 бита      | `false` (0) / `true` (1)                   | логические              |
| `str`  | адрес (32 б) | указатель на Pascal-строку в dmem          | строки                  |
| `void` | —            | —                                          | тип «нет значения»      |

`int` и `bool` — **значимые типы** (присваивание копирует значение). `str` — **ссылочный тип** (копируется адрес, не содержимое). Неявных преобразований нет.

#### 2.4 Литералы

**Целые** — десятичные цифры с опциональным унарным минусом; должны укладываться в int32.

**Булевы** — `true` / `false` (регистрозависимо).

**Строковые** — в двойных кавычках. Escape-последовательности: `\n`, `\t`, `\\`, `\"`. Каждый символ хранится в отдельном 32-битном слове. Перед символами — 32-битное слово длины (**Pascal-строка**). Строковый литерал размещается в dmem; в инструкцию встраивается его адрес.

#### 2.5 Выражения

Приоритет (от низкого к высокому):

```
=          присваивание          (правоассоциативно)
||         логическое ИЛИ
&&         логическое И
== !=      равенство
< <= > >=  сравнение
+ -        сложение/вычитание
* / %      умножение/деление/остаток
! -        унарные
()         вызов функции
```

Деление — целочисленное, усечение к нулю (`7/2=3`, `-7/2=-3`). Остаток сохраняет знак делимого. Переполнение — арифметика по модулю 2³².

#### 2.6 Операторы

`var x: int;` — начальное значение 0 (на это не следует опираться). `const` требует инициализатора и запрещает дальнейшее присваивание.

`break` / `continue` — только внутри цикла. `return` без значения — для `void`-функций.

#### 2.7 Встроенные функции

Предоставляются runtime-библиотекой, объявления не требуют:

| Функция                           | Результат | Действие                                        |
|-----------------------------------|-----------|-------------------------------------------------|
| `read_char()`                     | `int`     | Читает символ из потока ввода (−1 при EOF)      |
| `write_char(c: int)`              | `void`    | Пишет символ в поток вывода                     |
| `str_len(s: str)`                 | `int`     | Длина строки (слово-префикс)                    |
| `str_get(s: str, i: int)`         | `int`     | Код символа по индексу i                        |
| `str_set(s: str, i: int, c: int)` | `void`    | Установить символ по индексу i                  |
| `str_set_len(s: str, n: int)`     | `void`    | Установить слово-длину строки                   |

Ввод/вывод реализован через memory-mapped порты: `read_char()` читает из `0xFFFF0000`, `write_char()` пишет в `0xFFFF0004`.

#### 2.8 Неопределённое поведение и ошибки компиляции

**UB:** чтение переменной до инициализации; индексирование строки за пределами `[0, len-1]`; переполнение int32.

**Ошибки компиляции:** несовпадение типов; обращение к необъявленному имени; присваивание `const`; несоответствие типа возврата.

## Инструменты

### compiler.py — компилятор JL

```
python compiler.py <source.jl> [output_dir] [--inline]
python compiler.py -h | --help
```

**Аргументы:**

| Аргумент | Описание |
|----------|----------|
| `<source.jl>` | Исходный файл на JL |
| `[output_dir]` | Директория для результатов (по умолчанию `out/` из `config.py`) |
| `--inline` | Inline-режим встроенных функций (см. ниже) |

**Выходные файлы** (имя берётся из `<source.jl>` без расширения):

| Файл | Содержимое |
|------|------------|
| `<stem>.imem` | Бинарный образ памяти команд |
| `<stem>.dmem` | Бинарный образ памяти данных |
| `<stem>.lst` | Листинг: таблица меток + дизассемблер |
| `<stem>.ast` | AST в человекочитаемом виде |

**Точка входа.** По адресу 0 в imem компилятор всегда помещает инструкцию `JMP main`. Эмулятору достаточно стартовать с `PC=0` — файл меток для этого не нужен.

**Dead code elimination.** Компилятор анализирует достижимость функций от `main` (BFS по графу вызовов). В imem попадают только достижимые пользовательские функции и только нужные функции runtime-библиотеки.

**Режимы генерации встроенных функций:**

| Режим | Как работает | Когда выгоднее |
|-------|-------------|----------------|
| call (по умолчанию) | `__rt_*` генерируются как отдельные процедуры; вызов через `JSR` | много вызовов одной функции (экономия imem) |
| `--inline` | тело builtin вставляется прямо на месте вызова, без `JSR`/`LINK`/`RTS` | мало вызовов; выигрыш в тактах всегда |

Разница на тестовых программах:

| Программа | Δ инструкций | Δ тактов | Δ imem |
|-----------|-------------|----------|--------|
| cat | −14% | −18% | −15% |
| hello_world | −18% | −23% | −19% |
| hello_user_name | −13% | −21% | −13% |
| sort | +10% | −15% | +5% |
| double_precision | +10% | −8% | +7% |

Inline всегда быстрее по тактам (устраняются накладные расходы на вызов). По размеру imem inline выгоден при редких вызовах; при частых вызовах в цикле call экономит место.

**Формат листинга** (`.lst`):

```
; Таблица меток:
;        0  __entry
;        8  __rt_write_char
;      260  main
;
     0  402F000000000104                  jmp @260                    ; __entry
     8  02210D00FFFF0004                  movea.l #4294901764, A5     ; __rt_write_char
    16  01030D00                          move.l D0, (A5)
    20  42FF0000                          rts
   ...
   260  60210E0000000000                  link.l #0, A6               ; main
```

Три выровненных колонки: адрес (6 символов), hex (32 символа), мнемоника (28 символов). Метки — справа от мнемоники через `; `.

### emulator.py — эмулятор

```
python emulator.py <prog_name> [--input STRING | --input-file FILE]
                               [--dir DIR] [--trace] [--trace-limit N]
                               [--trace-out FILE] [--dump] [--max-cycles N]
python emulator.py -h | --help
```

**Аргументы:**

| Аргумент | Описание |
|----------|----------|
| `<prog_name>` | Имя программы — с расширением или без, с путём или без. `out/sort.imem`, `sort.jl`, `sort` — эквивалентны |
| `--input STRING` | Ввод строкой |
| `--input-file FILE` | Ввод из файла |
| `--dir DIR` | Директория с `.imem`/`.dmem` (по умолчанию `out/`) |
| `--trace` | Построчная трассировка тактов |
| `--trace-limit N` | Максимум строк трассировки на экран (по умолчанию 200) |
| `--trace-out FILE` | Сохранить полную трассировку в файл |
| `--dump` | Дамп регистров после завершения |
| `--max-cycles N` | Лимит тактов (по умолчанию 500 000) |

Без `--input` / `--input-file` — интерактивный режим: символы читаются из stdin лениво в момент обращения программы к порту ввода.

Точка входа — всегда `PC=0`. Файл меток не нужен.

### runtime.py — генератор runtime-библиотеки

Содержит логику генерации встроенных функций. Не запускается напрямую — используется компилятором.

| Класс | Назначение |
|-------|------------|
| `RuntimeEmitter` | Генерирует `__rt_*` как именованные процедуры (call-режим) |
| `InlineEmitter` | Генерирует тело builtin-операции прямо на месте вызова (inline-режим) |

Функция `reachable_fns(prog)` выполняет BFS от `main` и возвращает множество достижимых функций — основа dead code elimination.

### config.py — общие константы

```python
IO_IN           = 0xFFFF0000   # адрес порта ввода в dmem
IO_OUT          = 0xFFFF0004   # адрес порта вывода в dmem
DEFAULT_OUT_DIR = "out"        # выходная директория компилятора
DEFAULT_TRACE_LIMIT = 200      # лимит строк трассировки
```

## Архитектура процессора

### 1. Модель памяти

**Гарвардская архитектура** — imem и dmem физически разделены и адресуются независимо.

```
┌─────────────────────────────────────┐   ┌─────────────────────────────────────┐
│         Instruction memory (imem)   │   │         Data memory (dmem)          │
│         read-only at runtime        │   │         read-write                  │
├─────────────────────────────────────┤   ├─────────────────────────────────────┤
│  0: JMP main          ← __entry     │   │  0x0000: статические данные         │
│  8: __rt_write_char   \             │   │          (строки, Pascal-буферы)    │
│ ..  __rt_*             > runtime    │   │  ...                                │
│ N:  пользовательские /              │   │  0x1E000: стек (растёт вниз ↓)      │
│     функции                         │   │  ...                                │
│ M:  main                            │   │  0xFFFF0000: порт ввода  (IO_IN)    │
│ ..  HALT                            │   │  0xFFFF0004: порт вывода (IO_OUT)   │
└─────────────────────────────────────┘   └─────────────────────────────────────┘
         ↑ PC адресует сюда                        ↑ A0–A7, SP адресуют сюда
```

**Машинное слово** — 32 бита, big-endian. Одно слово хранит: `int`, `bool`, один символ строки или адрес.

**Точка входа** — всегда адрес 0 imem. Компилятор генерирует там `JMP main`. Это позволяет размещать runtime-функции до `main` без необходимости передавать адрес `main` отдельно.

### 2. Регистровый файл

```
Регистры данных  D0–D7   8 × 32 бита   арифметика, временные значения
Адресные рег-ры  A0–A7   8 × 32 бита   указатели в dmem; A6 = FP, A7 = SP
Program Counter  PC      32 бита       адрес текущей инструкции в imem
Status Register  SR      4 бита        флаги N Z V C
```

Флаги SR:

| Флаг | Название | Условие |
|------|----------|---------|
| N | Negative | результат отрицателен |
| Z | Zero | результат равен нулю |
| V | Overflow | знаковое переполнение |
| C | Carry | беззнаковый перенос |

Флаги устанавливаются арифметическими и логическими инструкциями. `move`/`movea` устанавливают только N и Z. Ветвления и `link`/`unlk` флаги не изменяют.

**Соглашения компилятора:**

| Регистр | Роль |
|---------|------|
| D0 | возвращаемое значение; главный временный |
| D1–D5 | рабочие (caller-saved через фрейм) |
| A0 | первый str-аргумент |
| A1 | вспомогательный адресный |
| A5 | адрес IO-порта (временный) |
| A6 | frame pointer (сохраняется через link/unlk) |
| A7 | stack pointer |

### 3. Режимы адресации

Все режимы применяются к dmem. Выборка инструкций идёт через PC из imem отдельно.

| Режим | Синтаксис | Код | Вычисление EA | Extra слов |
|-------|-----------|-----|---------------|------------|
| Регистр данных | `Dn` | 0x0 | значение Dn | 0 |
| Регистр адреса | `An` | 0x1 | значение An | 0 |
| Непосредственный | `#imm` | 0x2 | константа из imem | 1 |
| Косвенный | `(An)` | 0x3 | An | 0 |
| Пост-инкремент | `(An)+` | 0x4 | An, затем An += шаг | 0 |
| Пред-декремент | `-(An)` | 0x5 | An -= шаг, затем An | 0 |
| Со смещением | `d(An)` | 0x6 | An + d | 1 |
| С индексом | `d(An,Xn)` | 0x7 | An + Xn + d | 2 |
| Нет операнда | — | 0xF | — | 0 |

Шаг для `(An)+` / `-(An)`: 4 байта (`.l`), 1 байт (`.b`).

### 4. Кодирование инструкций

Каждая инструкция — **базовое слово** (32 бита) плюс 0–3 дополнительных слова по 32 бита.

```
Базовое слово:
 31      24 23   20 19   16 15   12 11    8  7   6        0
 ┌─────────┬───────┬───────┬───────┬───────┬───┬──────────┐
 │ opcode  │ srcM  │ dstM  │ srcR  │ dstR  │ sz│ reserved │
 │  8 бит  │ 4 бит │ 4 бит │ 4 бит │ 4 бит │ 1 │  7 бит   │
 └─────────┴───────┴───────┴───────┴───────┴───┴──────────┘

opcode  [31:24] — код операции
srcM    [23:20] — режим адресации источника
dstM    [19:16] — режим адресации приёмника
srcR    [15:12] — регистр источника (0–7: D0–D7, 8–15: A0–A7)
dstR    [11: 8] — регистр приёмника
sz      [   7]  — 0 = long (32 бит), 1 = byte (8 бит)
reserved[ 6: 0] — всегда 0
```

Дополнительные слова следуют в порядке: src extra → dst extra.

**Такты.** Каждая выборка слова из imem — 1 такт. Исполнение — ещё 1 такт:

```
Тактов = (количество слов в инструкции) + 1
```

| Количество слов | Тактов | Примеры |
|----------------|--------|---------|
| 1 | **2** | reg→reg, (An), rts, halt, unlk |
| 2 | **3** | #imm→reg, d(An)→reg, jmp/jsr/ветвления, link |
| 3 | **4** | #imm→d(An), MEM_IDX→reg |
| 4 | **5** | #imm→d(An,Xn) |

### 5. Набор инструкций

#### 5.1 Таблица опкодов

| Код | Мнемоника | Описание |
|-----|-----------|----------|
| 0x01 | MOVE | Пересылка данных; флаги N, Z |
| 0x02 | MOVEA | Пересылка в адресный регистр; флаги не изменяются |
| 0x10 | ADD | dst ← dst + src; флаги N Z V C |
| 0x11 | SUB | dst ← dst − src; флаги N Z V C |
| 0x12 | MUL | Dn ← Dn × src (знаковое, 32-бит); флаги N Z |
| 0x13 | DIV | Dn ← Dn / src (усечение к нулю); флаги N Z |
| 0x14 | CMP | Флаги по dst − src, результат не сохраняется; флаги N Z V C |
| 0x20 | AND | Побитовое И; флаги N Z |
| 0x21 | OR | Побитовое ИЛИ; флаги N Z |
| 0x22 | XOR | Побитовое исключающее ИЛИ; флаги N Z |
| 0x23 | NOT | Dn ← ~Dn; флаги N Z |
| 0x30 | ASL | Арифметический сдвиг влево |
| 0x31 | ASR | Арифметический сдвиг вправо (сохраняет знак) |
| 0x32 | LSL | Логический сдвиг влево |
| 0x33 | LSR | Логический сдвиг вправо (заполнение нулями) |
| 0x40 | JMP | PC ← addr |
| 0x41 | JSR | SP−=4; mem[SP]←PC; PC←addr |
| 0x42 | RTS | PC←mem[SP]; SP+=4 |
| 0x50 | BEQ | Переход если Z=1 |
| 0x51 | BNE | Переход если Z=0 |
| 0x52 | BLT | Переход если N≠V |
| 0x53 | BGT | Переход если Z=0 и N=V |
| 0x54 | BLE | Переход если Z=1 или N≠V |
| 0x55 | BGE | Переход если N=V |
| 0x56 | BMI | Переход если N=1 |
| 0x57 | BPL | Переход если N=0 |
| 0x58 | BCC | Переход если C=0 |
| 0x59 | BCS | Переход если C=1 |
| 0x5A | BVC | Переход если V=0 |
| 0x5B | BVS | Переход если V=1 |
| 0x5C | BRA | Безусловный |
| 0x60 | LINK | Создание стекового фрейма |
| 0x61 | UNLK | Уничтожение стекового фрейма |
| 0xFF | HALT | Остановка процессора |

Все адреса переходов (JMP, JSR, ветвления) — абсолютные адреса в imem, хранятся как 32-битное extra-слово.

#### 5.2 LINK / UNLK — управление фреймом

```
link An, #d:   SP−=4; mem[SP]←An; An←SP; SP+=d  (d отрицательное)
unlk An:       SP←An; An←mem[SP]; SP+=4
```

После `link A6, #-N` локальные переменные доступны по `-4(A6)`, `-8(A6)`, ..., `-N(A6)`.

### 6. Организация памяти

#### 6.1 Карта памяти данных (dmem)

```
Адрес         Содержимое
──────────────────────────────────────────────────────────────────
0x00000000    Статические данные: Pascal-строки и буферы
              в порядке первого появления в исходном тексте.

              Пример — hello_user_name:
              0x0000  "What is your name?\n"   (80 байт)
              0x0050  "Hello, "                (32 байта)
              0x0070  "!\n"                    (12 байт)
              0x007C  "Hello, stranger!\n"     (72 байта)
              0x00C4  name_buf                 (260 байт, 65 слов)

              Пример — sort:
              0x0000  "Sorted: "  0x0024  "Sum: "  0x003C  "Avg: "
──────────────────────────────────────────────────────────────────
0x0001E000    Начальное значение SP; стек растёт вниз.
              Стековые фреймы функций.
──────────────────────────────────────────────────────────────────
0xFFFF0000    IO_IN  — чтение → следующий токен ввода (−1 при EOF)
0xFFFF0004    IO_OUT — запись → токен в буфер вывода
──────────────────────────────────────────────────────────────────
```

Pascal-строка в dmem:

```
Адрес    Значение      Смысл
base+0   0x00000003    длина (len = 3)
base+4   0x00000048    'H'
base+8   0x00000069    'i'
base+12  0x0000000A    '\n'
```

#### 6.2 Карта памяти команд (imem)

```
Адрес    Содержимое
──────────────────────────────────────────────────────────────────
0        __entry: JMP main           ← всегда
8        runtime-функции (только нужные, в фиксированном порядке):
         __rt_write_char, __rt_read_char, __rt_str_len,
         __rt_str_get, __rt_str_set, __rt_str_set_len,
         __rt_print_str, __rt_read_line
N        пользовательские функции (только достижимые от main)
M        main
...      HALT
──────────────────────────────────────────────────────────────────
```

#### 6.3 Стековый фрейм

```
Адрес        Содержимое
──────────────────────────────────────────────────────────────────
SP (до jsr)
SP − 4       адрес возврата (push при jsr)
SP − 8       сохранённый A6 вызывающей стороны (push при link)
             ← A6 (новый FP) указывает сюда
A6 − 4       первый локальный слот / сохранённый регистр
A6 − 8       второй слот
...
A6 − N       N/4-й слот
             ← SP после link
──────────────────────────────────────────────────────────────────
```

#### 6.4 Сводная таблица: конструкция языка → память

| Конструкция | Compile time | Runtime |
|-------------|-------------|---------|
| Целочисленный литерал | extra word в imem | читается декодером |
| Строковый литерал | Pascal-строка в dmem | адрес передаётся как `#imm` |
| Локальная переменная | слот `d(A6)` в фрейме | `move.l d(A6), Dn` |
| Параметр функции | caller кладёт в D0/A0 | читается из регистра |
| Функция | блок в imem | `JSR @addr` → `LINK` → тело → `UNLK` → `RTS` |
| str-буфер (mutable) | зарезервирован в dmem | адрес в A0 |
| IO (read/write) | адрес порта = `#imm` | `move.l (A5), Dn` / `move.l Dn, (A5)` |

### 7. Ввод-вывод

Memory-mapped I/O. Прерываний нет — polling.

```asm
; read_char() → D0
movea.l #0xFFFF0000, A5
move.l  (A5), D0            ; D0 = следующий символ (−1 при EOF)

; write_char(D0)
movea.l #0xFFFF0004, A5
move.l  D0, (A5)            ; отправить символ в буфер вывода
```

### 8. Примеры кодирования

```
Инструкция                    Hex                          Байт  Тактов
──────────────────────────────────────────────────────────────────────────
move.l D2, D3                01 00 23 00                    4     2
move.l #42, D0               01 20 00 00  00 00 00 2A       8     3
move.l D1, -4(A6)            01 06 1E 00  FF FF FF FC       8     3
move.l #0, -8(A6)            01 26 0E 00  00 00 00 00
                                          FF FF FF F8       12    4
cmp.l D3, D1                 14 00 31 00                    4     2
cmp.l #32, D1                14 20 01 00  00 00 00 20       8     3
jsr @512                     41 2F 00 00  00 00 02 00       8     3
bge @84                      55 2F 00 00  00 00 00 54       8     3
```

### 9. Пример полного цикла исполнения

`cmp.l #0, -4(A6)` (12 байт, 4 такта):

```
Состояние до: PC=304, A6=0x1DFF8, dmem[0x1DFF4]=5

Такт 1 — fetch base word:
  imem[304..307] = 0x14206E00 → PC=308
  decode: opcode=CMP, srcM=IMMED, dstM=MEM_DISP, dstR=A6

Такт 2 — fetch src extra (immediate):
  imem[308..311] = 0x00000000 (src=0) → PC=312

Такт 3 — fetch dst extra (смещение MEM_DISP):
  imem[312..315] = 0xFFFFFFFC (d=−4) → PC=316
  EA = A6 + (−4) = 0x1DFF4

Такт 4 — execute:
  dst = dmem[0x1DFF4] = 5
  5 − 0 = 5 → N=0, Z=0, V=0, C=0
```

PC к моменту исполнения уже указывает на следующую инструкцию (316). Именно это является «явной сменой машинного слова» при выборке инструкции переменной длины.

## Транслятор

### Интерфейс командной строки

```
python compiler.py <source.jl> [output_dir] [--inline]
python compiler.py -h | --help
```

**Аргументы:**

| Аргумент | Тип | Описание |
|----------|-----|----------|
| `<source.jl>` | обязательный | Исходный файл программы на языке JL |
| `[output_dir]` | необязательный | Директория для выходных файлов. По умолчанию — значение `DEFAULT_OUT_DIR` из `config.py` (`"out"`) |
| `--inline` | флаг | Inline-режим встроенных функций (см. ниже) |

**Выходные файлы** (имя берётся из `<source.jl>` без расширения — `<stem>`):

| Файл | Содержимое |
|------|------------|
| `<stem>.imem` | Бинарный образ памяти команд (instruction memory) |
| `<stem>.dmem` | Бинарный образ памяти данных (data memory) |
| `<stem>.lst` | Листинг: таблица меток + дизассемблированный код |
| `<stem>.ast` | Абстрактное синтаксическое дерево в текстовом виде |

**Примеры:**

```bash

python compiler.py hello.jl ./build         # вывод в ./build/

```

**Stdout компилятора:**

```

Точка входа: PC=0 → JMP main (260)
```

### Этапы трансляции

Компилятор реализован как однофайловое консольное приложение `compiler.py` и проходит четыре последовательных этапа:

```
Исходный текст (.jl)
        │
        ▼
┌───────────────┐
│   1. Лексер   │  lex()        → список Token
└───────────────┘
        │
        ▼
┌───────────────┐
│   2. Парсер   │  Parser       → Program (AST)
└───────────────┘
        │
        ▼
┌───────────────────────────────┐
│  3. Анализ достижимости       │  reachable_fns()  → нужные функции
└───────────────────────────────┘
        │
        ▼
┌───────────────────────────────┐
│  4. Кодогенерация             │  CodeGen          → imem, dmem
└───────────────────────────────┘
        │
        ▼
  .imem  .dmem  .lst  .ast
```

#### Этап 1 — Лексический анализ (`lex`)

Функция `lex(src: str) → list[Token]` выполняет однопроходной посимвольный разбор исходного текста.

Обрабатывает:
- Пробельные символы и переводы строк (игнорируются, строка трекается для сообщений об ошибках).
- Комментарии: однострочные `// ...` и блочные `/* ... */`.
- Строковые литералы с escape-последовательностями `\n`, `\t`, `\\`, `\"`.
- Целочисленные литералы (десятичные).
- Идентификаторы и ключевые слова (разграничиваются по таблице `KEYWORDS`).
- Одно- и двухсимвольные операторы (`==`, `!=`, `<=`, `>=`, `&&`, `||` и одиночные).

Каждый `Token` несёт поля `kind`, `value` и `line`. При ошибке бросается `LexError` с номером строки.

#### Этап 2 — Синтаксический анализ (`Parser`)

Класс `Parser` реализует **рекурсивный спуск** с ручным управлением приоритетами операторов (Pratt-style без таблиц). Строит **AST (Abstract Syntax Tree)** из узлов:

| Категория | Узлы AST |
|-----------|----------|
| Программа | `Program`, `FnDecl`, `Param` |
| Операторы | `Block`, `VarDecl`, `Assign`, `IfStmt`, `WhileStmt`, `ForStmt`, `ReturnStmt`, `BreakStmt`, `ContinueStmt`, `ExprStmt` |
| Выражения | `Literal`, `Ident`, `BinOp`, `UnOp`, `Call` |

Приоритеты выражений реализованы цепочкой методов: `parse_assign → parse_or → parse_and → parse_eq → parse_rel → parse_add → parse_mul → parse_unary → parse_primary`. При ошибке бросается `ParseError` с номером строки.

После парсинга AST сериализуется в файл `.ast` через метод `pretty()` каждого узла.

#### Этап 3 — Анализ достижимости

Перед генерацией кода `reachable_fns(prog)` из `runtime.py` выполняет **BFS от `main`** по графу вызовов:

1. Для каждой пользовательской функции `collect_calls()` рекурсивно обходит её AST и собирает все имена вызываемых функций.
2. BFS: начинает с `{"main"}`, переходит по прямым вызовам, для каждого builtin-имени добавляет транзитивные `__rt_*`-зависимости из таблицы `RT_CALLS`.
3. Возвращает множество достижимых имён.

**Результат:** в imem попадают только функции, реально вызываемые из `main` — прямо или косвенно. Недостижимые функции не компилируются (dead code elimination).

#### Этап 4 — Кодогенерация (`CodeGen`)

Класс `CodeGen` выполняет однопроходную генерацию машинного кода. Хранит два байтовых буфера: `code` (imem) и `data` (dmem).

**Структура сгенерированного imem:**

```
Адрес 0:   __entry: JMP main        ← всегда первым
           __rt_write_char           \
           __rt_read_char             |
           __rt_str_len               |  только нужные,
           __rt_str_get               |  в фиксированном
           __rt_str_set               |  порядке
           __rt_str_set_len          /
           пользовательские функции  ← только достижимые
           main                      ← точка входа
           HALT
```

**Генерация функции** (`compile_fn`):

1. Выделить слоты для параметров в таблице символов (`Scope`).
2. Emit `LINK A6, #-N` — создать стековый фрейм (N вычисляется после обхода тела).
3. Emit `MOVE Dn/An, d(A6)` — сохранить параметры из регистров во фрейм.
4. Компилировать тело (`compile_block`).
5. Emit `UNLK A6; RTS` (или `HALT` для `main`).
6. Пропатчить `LINK` правильным значением N.

**Соглашение о вызовах:**
- Первый `int`/`bool` аргумент → D0, второй → D1.
- Первый `str` аргумент (адрес) → A0, второй → A1.
- Возвращаемое значение: `int`/`bool` → D0, `str` → A0.

**Генерация выражений** (`compile_expr`):

Результат всегда в D0 (int/bool) или A0 (str). Для вложенных выражений с несколькими операндами промежуточные значения сохраняются на стек (`-(A7)` / `(A7)+`).

**Оптимизации кодогенератора:**

| Оптимизация | Описание |
|-------------|----------|
| Прямое ветвление | Условия в `if`/`while`/`for` компилируются напрямую в `CMP + Bxx` через `compile_cond()` — без промежуточного вычисления bool в регистре |
| Immediate-правый операнд | `expr OP literal` → `ADD/SUB/CMP #imm, D0` без push/pop |
| Ident-ident сравнение | `a < b` (оба переменные) → `MOVE d(A6), D1; MOVE d(A6), D0; CMP D0, D1` без стека |
| `-Literal` → `Imm(-n)` | Унарный минус от литерала превращается в одну `MOVE #-n, D0` |
| Deduplication строк | Одинаковые строковые литералы размещаются в dmem однократно (`str_cache`) |
| Один аргумент без стека | При одном аргументе функции push/pop не генерируется |

**Разрешение меток (fixup):**

Адреса переходов (`JMP`, `JSR`, ветвления) не известны в момент генерации, поэтому в extra-слово записывается `0`, а в список `fixups` добавляется запись `(offset, label_name)`. После компиляции всех функций `_fixup()` пробегает по списку и подставляет реальные адреса из словаря `labels`.

**Два режима встроенных функций:**

| Режим | Флаг | Механизм |
|-------|------|----------|
| call (по умолчанию) | — | `RuntimeEmitter` генерирует `__rt_*` как именованные процедуры; каждый вызов builtin → `JSR __rt_*` |
| inline | `--inline` | `__rt_*` не генерируются; `InlineEmitter` вставляет тело операции прямо на месте вызова — без `JSR`/`LINK`/`RTS` |

Inline всегда уменьшает число тактов (−8…−23%), но увеличивает размер imem при частых вызовах builtin в цикле.

**Генерация листинга** (`.lst`):

```
; Таблица меток:
;        0  __entry
;        8  __rt_write_char
;      260  main
;
     0  402F000000000104                  jmp @260                    ; __entry
     8  02210D00FFFF0004                  movea.l #4294901764, A5     ; __rt_write_char
    16  01030D00                          move.l D0, (A5)
    20  42FF0000                          rts
   260  60210E0000000000                  link.l #0, A6               ; main
```

Три выровненные колонки: адрес (6 символов), hex (32 символа), мнемоника (28 символов). Метки — справа через `; `. Таблица всех меток — в начале файла в виде комментариев.
