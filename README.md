## Язык программирования
### 1.Синтаксис

Расширенная форма Бэкуса-Наура:

``` ebnf
<program>     ::= { <decl> }

<decl>        ::= <var_decl>
               | <fn_decl>

(* Объявления *)
<var_decl>    ::= "var" <ident> [":" <type>] ["=" <expr>] ";"
               | "const" <ident> [":" <type>] "=" <expr> ";"

<fn_decl>     ::= "fn" <ident> "(" [<param_list>] ")" [":" <type>] <block>

<param_list>  ::= <param> { "," <param> }
<param>       ::= <ident> ":" <type>

<type>        ::= "int" | "bool" | "str" | "void"
               | <ident>            (* пользовательский тип *)

(* Блок и операторы *)
<block>       ::= "{" { <stmt> } "}"

<stmt>        ::= <var_decl>
               | <assign_stmt>
               | <if_stmt>
               | <while_stmt>
               | <for_stmt>
               | <return_stmt>
               | <break_stmt>
               | <continue_stmt>
               | <expr_stmt>
               | <block>

<assign_stmt> ::= <ident> ["[" <expr> "]"] "=" <expr> ";"

<if_stmt>     ::= "if" "(" <expr> ")" <block> [ "else" (<if_stmt> | <block>) ]

<while_stmt>  ::= "while" "(" <expr> ")" <block>

<for_stmt>    ::= "for" "(" (<var_decl> | <assign_stmt> | ";")
                            <expr> ";"
                            (<assign_stmt_no_semi> | <expr>) ")" <block>
(* assign_stmt_no_semi — присвоение без финальной ";" для заголовка for *)

<return_stmt> ::= "return" [<expr>] ";"
<break_stmt>  ::= "break" ";"
<continue_stmt>::= "continue" ";"

<expr_stmt>   ::= <expr> ";"

(* Выражения по возрастанию приоритета *)
<expr>        ::= <assign_expr>

<assign_expr> ::= <or_expr>                              (* rvalue *)
               | <ident> "=" <assign_expr>               (* l = r  *)

<or_expr>     ::= <and_expr> { "||" <and_expr> }
<and_expr>    ::= <eq_expr>  { "&&" <eq_expr>  }
<eq_expr>     ::= <rel_expr> { ("==" | "!=") <rel_expr> }
<rel_expr>    ::= <add_expr> { ("<" | "<=" | ">" | ">=") <add_expr> }
<add_expr>    ::= <mul_expr> { ("+" | "-") <mul_expr> }
<mul_expr>    ::= <unary_expr> { ("*" | "/" | "%") <unary_expr> }
<unary_expr>  ::= ("!" | "-") <unary_expr>
               | <postfix_expr>

<postfix_expr>::= <primary_expr>
               | <postfix_expr> "[" <expr> "]"           (* индексирование *)
               | <postfix_expr> "(" [<arg_list>] ")"     (* вызов функции *)

<primary_expr>::= <literal>
               | <ident>
               | "(" <expr> ")"
               | <string_lit>

<arg_list>    ::= <expr> { "," <expr> }

(* Литералы *)
<literal>     ::= <int_lit> | <bool_lit>
<int_lit>     ::= ["-"] DIGIT { DIGIT }
<bool_lit>    ::= "true" | "false"
<string_lit>  ::= '"' { <str_char> } '"'
<str_char>    ::= любой символ кроме '"' и '\n' | escape_sequence
<escape_sequence> ::= "\" ("n" | "t" | "\" | '"')

<ident>       ::= LETTER { LETTER | DIGIT | "_" }

LETTER        ::= [a-z] | [A-Z] | "_"
DIGIT         ::= [0-9]
```

### 2. Семантика языка

#### 2.1 Стратегия вычислений

Язык использует **строгую стратегию вычислений**: каждое выражение вычисляется полностью в момент его встречи, до того как его значение передаётся куда-либо ещё. Аргументы функции вычисляются **до вызова**, слева направо.

```
fn add(a: int, b: int) : int { return a + b; }

var x: int = add(2 + 3, 4 * 5);
// Шаг 1: вычислить 2 + 3 → 5
// Шаг 2: вычислить 4 * 5 → 20
// Шаг 3: вызвать add(5, 20) → 25
// Шаг 4: присвоить x = 25
```

Порядок вычисления подвыражений в бинарном операторе — **слева направо**:

```
var x: int = f() + g();
// f() вычисляется первым, g() — вторым
```

**Ленивая стратегия** применяется **только** к логическим операторам `&&` и `||`:

```
false && side_effect()   // side_effect() НЕ вызывается
true  || side_effect()   // side_effect() НЕ вызывается
```


#### 2.2 Области видимости

##### 2.2.1 Статическая (лексическая) область видимости

Язык использует **статическую лексическую область видимости**: имя всегда разрешается в том блоке, где оно объявлено, не в том, откуда вызвана функция.

##### 2.2.2 Структура областей видимости

Существуют три уровня:

**Глобальный уровень** — объявления `fn` и `var`/`const` на верхнем уровне файла. Видны во всём файле от начала до конца.

**Уровень функции** — параметры функции и локальные переменные в её теле. Параметры видны с начала тела функции. Локальные переменные видны с точки объявления до конца блока, в котором объявлены.

**Уровень блока** — переменная, объявленная внутри `{ }`, видна только внутри этих скобок:

```
fn example() : void {
    var a: int = 1;       // видна до конца тела функции
    if (a > 0) {
        var b: int = 2;   // видна только внутри if-блока
    }
    // b здесь недоступна
}
```

##### 2.2.3 Затенение (shadowing)

Внутренняя переменная с тем же именем **затеняет** внешнюю. Внешняя при этом не уничтожается — она становится снова видна после закрывающей скобки внутреннего блока:

```
var x: int = 10;
fn example() : void {
    var x: int = 20;   // затеняет глобальный x
    // x == 20
}
// глобальный x по-прежнему 10
```

##### 2.2.4 Функции: видимость и рекурсия

Функции видны в глобальной области видимости и могут вызывать себя рекурсивно. Взаимная рекурсия возможна при объявлении обеих функций на верхнем уровне (порядок объявления не важен — все имена верхнего уровня доступны с самого начала).


#### 2.3. Типизация

##### 2.3.1 Статическая, явная

Язык — **статически типизированный** язык. Тип каждой переменной и параметра задаётся явно при объявлении. Компилятор проверяет совместимость типов до генерации кода; ошибки типов исключены во время выполнения.

```
var n: int = 42;        // правильно
var n: int = "hello";   // ошибка компиляции
```

##### 2.3.2 Встроенные типы

| Тип    | Размер в машинном слове | Диапазон                                 | Назначение                  |
|--------|-------------------------|------------------------------------------|-----------------------------|
| `int`  | 1 слово (32 бита)       | −2 147 483 648 … 2 147 483 647           | целые числа со знаком       |
| `bool` | 1 слово (32 бита)       | `false` (0) / `true` (1)                 | логические значения         |
| `str`  | указатель на Pascal-строку | —                                     | строки (Length-prefixed)    |
| `void` | —                        | —                                        | тип "нет значения" для функций |

`int` и `bool` — **значимые типы** (value types): присваивание копирует значение.

`str` — **ссылочный тип** (reference type): переменная хранит адрес строки в памяти данных. Присваивание `str` копирует адрес, а не содержимое. Два имени могут указывать на одну строку.

##### 2.3.3 Неявные преобразования

Язык **не выполняет неявных преобразований**. Передача `bool` туда, где ожидается `int`, и наоборот — ошибка компиляции. Явных операторов приведения нет.

#### 2.4. Литералы

##### 2.4.1 Целочисленные литералы (`int`)

Записываются как последовательность цифр, опционально с унарным минусом:

```
0
42
-7
1000000
```

Допустимы только десятичные цифры. Шестнадцатеричная, восьмеричная, двоичная запись не предусмотрены. Значение должно укладываться в 32-битный знаковый диапазон; выход за границы — ошибка компиляции.

##### 2.4.2 Булевы литералы (`bool`)

Ровно два значения:

```
true
false
```

Регистрозависимы (`True` — ошибка).

##### 2.4.3 Строковые литералы (`str`)

Заключаются в двойные кавычки:

```
"hello"
"What is your name?\n"
""
```

Допустимые escape-последовательности внутри строки:

| Запись | Значение                    |
|--------|-----------------------------|
| `\n`   | перевод строки (ASCII 10)   |
| `\t`   | горизонтальная табуляция (ASCII 9) |
| `\\`   | обратный слеш               |
| `\"`   | двойная кавычка             |

Каждый символ строки хранится в **отдельном 32-битном слове** (один символ — одно машинное слово). Перед символами хранится 32-битное слово длины. Это **Pascal-строка (Length-prefixed)**. Строковый литерал размещается компилятором в секции данных; значением выражения-литерала является адрес его начала.


#### 2.5. Выражения и их значения

##### 2.5.1 Арифметика

Операнды — `int`. Результат — `int`. Деление (`/`) — целочисленное, усечение к нулю (truncate toward zero): `7 / 2 = 3`, `-7 / 2 = -3`. Остаток (`%`) сохраняет знак делимого: `-7 % 2 = -1`.

Переполнение при арифметике не является ошибкой — значение берётся по модулю 2³².

##### 2.5.2 Сравнение

Операнды — `int` или `bool` (оба одного типа). Результат — `bool`. Операторы: `==`, `!=`, `<`, `<=`, `>`, `>=`. Сравнение `bool` через `==`/`!=` сравнивает 0 и 1.

##### 2.5.3 Логические операторы

Операнды — `bool`. Результат — `bool`. `&&` и `||` — с ленивым вычислением. `!` — унарное логическое отрицание.

##### 2.5.4 Унарный минус

Операнд — `int`. Результат — `int`. Значение: `0 - x`.

##### 2.5.5 Приоритет операторов (от низкого к высокому)

```
присваивание      =           (правоассоциативно)
логическое или    ||
логическое и      &&
равенство         ==  !=
сравнение         <  <=  >  >=
сложение          +  -
умножение         *  /  %
унарные           !  -
постфиксные       []  ()      (вызов функции, индексирование)
```

##### 2.5.6 Индексирование строки

`str_get(s, i)` — встроенная функция, возвращает `int` (код символа на позиции `i`). Прямой синтаксис `s[i]` компилируется в обращение к памяти (аналогично). Индекс `i` — `int`, отсчёт с нуля. Выход за пределы длины — неопределённое поведение.

 ##### 2.5.7 Вызов функции

```
f()
f(a, b, c)
```

Все аргументы вычисляются слева направо до передачи управления. Вызов — выражение; его значением является то, что вернул `return` (или «ничего» для `void`-функций).


#### 2.6 Операторы

##### 2.6.1 Объявление переменной

```
var <имя> : <тип> = <выражение> ;
var <имя> : <тип> ;
const <имя> : <тип> = <выражение> ;
```

`var` без инициализатора — переменная имеет **неопределённое начальное значение** (для `int` и `bool` это 0 в текущей реализации, но на это опираться не следует). `const` требует инициализатора; после объявления значение изменить нельзя (попытка присвоения — ошибка компиляции).

##### 2.6.2 Присваивание

```
<имя> = <выражение> ;
```

Вычисляет правую часть, помещает результат в переменную. Правая часть — выражение того же типа, что переменная. Цепочка присваиваний (`a = b = expr`) не допускается как отдельный оператор; `=` в позиции выражения разрешён только как единственный уровень (см. приоритеты).

##### 2.6.3 Ветвление

```
if (<условие>) <блок>
if (<условие>) <блок> else <блок>
if (<условие>) <блок> else if (<условие>) <блок> ...
```

Условие — выражение типа `bool`. Ветвь `else` привязывается к ближайшему предшествующему `if` (dangling-else разрешается жадно). Блок выполняется только если условие `true`.

**Пошаговое выполнение `if`:**

1. Вычислить `<условие>`.
2. Если `true` — войти в then-блок, выполнить его операторы по порядку, выйти из конструкции.
3. Если `false` и есть `else` — войти в else-блок, выполнить его, выйти.
4. Если `false` и `else` нет — пропустить конструкцию.

##### 2.6.4 Цикл while

```
while (<условие>) <блок>
```

**Пошаговое выполнение:**

1. Вычислить `<условие>`.
2. Если `false` — выйти из цикла.
3. Если `true` — выполнить тело блока.
4. Перейти к шагу 1.

`break` — немедленно выйти из ближайшего охватывающего цикла. `continue` — немедленно перейти к проверке условия.

##### 2.6.5 Цикл for

```
for (<инициализация>; <условие>; <шаг>) <блок>
```

Эквивалентен:

```
{
    <инициализация>
    while (<условие>) {
        <блок>
        <шаг>;
    }
}
```

Переменная, объявленная в `<инициализации>`, видна только внутри конструкции `for`.

##### 2.6.6 Возврат из функции

```
return <выражение> ;
return ;
```

Немедленно завершает выполнение текущей функции. `return` без значения используется в функциях с типом возврата `void`. Управление передаётся вызывающей стороне; выражение после `return` в теле функции не достигается (мёртвый код).

##### 2.6.7 Блок

```
{ <оператор>* }
```

Создаёт новую область видимости. Операторы выполняются последовательно.


#### 2.7 Функции

##### 2.7.1 Объявление

```
fn <имя>(<параметр>*) : <тип_возврата> { <тело> }
```

Параметры — все типа, переданные **по значению** для `int` и `bool` и **по ссылке (адресу)** для `str`. Изменение `str`-параметра внутри функции изменяет строку, на которую указывает переданный адрес.

##### 2.7.2 Стек вызовов

Каждый вызов функции создаёт **стековый фрейм**, содержащий:

- адрес возврата;
- сохранённый фрейм-указатель (A6) вызывающей стороны;
- локальные переменные (по 4 байта на каждую).

После `return` фрейм уничтожается, локальные переменные недоступны. Указатели на локальные переменные, сохранённые вовне, указывают на мусор после завершения функции.

##### 2.7.3 Встроенные функции

Следующие функции предоставляются рантаймом и не требуют объявления:

| Функция                        | Тип результата | Действие                                              |
|-------------------------------|----------------|-------------------------------------------------------|
| `read_char()`                 | `int`          | Читает один символ из потока ввода (−1 при EOF)       |
| `write_char(c: int)`          | `void`         | Пишет один символ в поток вывода                      |
| `str_len(s: str)`             | `int`          | Возвращает длину строки (слово-префикс)               |
| `str_get(s: str, i: int)`     | `int`          | Возвращает код i-го символа                           |
| `str_set(s: str, i: int, c: int)` | `void`     | Устанавливает i-й символ                             |
| `str_set_len(s: str, n: int)` | `void`         | Устанавливает слово-длину строки                      |

Ввод/вывод реализован через **memory-mapped порты**: `read_char()` читает из адреса `0xFFFF0000`, `write_char()` пишет в `0xFFFF0004`. Порты отображаются в пространство памяти данных и доступны штатными инструкциями `move`.


#### 2.8 Неопределённое поведение (UB) и ошибки компиляции

**UB** (результат непредсказуем, программа корректна синтаксически):

- чтение переменной `var` до её инициализации;
- индексирование строки за пределами `[0, len-1]`;
- вызов `read_char()` после EOF (возвращает −1, но последующее поведение при использовании −1 как кода символа непредсказуемо для вывода);
- переполнение 32-битного диапазона `int` (арифметика по модулю 2³², но семантика флагов не гарантирована).

**Ошибки компиляции** (программа не будет скомпилирована):

- несовпадение типов в выражении или присваивании;
- обращение к необъявленному имени;
- присваивание `const`-переменной;
- `return <выражение>` в функции с возвратом `void` или `return` без выражения в функции с ненулевым типом возврата.

 
### Организация памяти
---

### 1. Модель памяти процессора

#### 1.1 Гарвардская архитектура

Процессор использует **Гарвардскую архитектуру**: память команд (imem) и память данных (dmem) физически разделены и адресуются независимо. Программный счётчик (PC) всегда указывает в imem; все переменные, строки, стек и порты ввода-вывода находятся в dmem. Запись в imem во время выполнения невозможна.

```
┌─────────────────────────────────────┐   ┌─────────────────────────────────────┐
│         Instruction memory          │   │            Data memory              │
│  (imem, read-only at runtime)       │   │            (dmem)                   │
├─────────────────────────────────────┤   ├─────────────────────────────────────┤
│ 0x0000 : процедура 1 (первая        │   │ 0x0000 : статические данные         │
│          функция в программе)       │   │         (строки, паскаль-буферы)    │
│ ...                                 │   │ ...                                 │
│ N      : процедура 2                │   │ 0x00C4 : name_buf (буфер ввода)     │
│ ...                                 │   │ ...                                 │
│ M      : main                       │   │ 0x0064 : массив arr (sort)          │
│ ...                                 │   │ ...                                 │
│                                     │   │ 0x1E000: стек (растёт вниз ↓)       │
│                                     │   │ ...                                 │
│                                     │   │ 0xFFFF0000 : порт ввода  (IO_IN)   │
│                                     │   │ 0xFFFF0004 : порт вывода (IO_OUT)  │
└─────────────────────────────────────┘   └─────────────────────────────────────┘
         ↑ PC адресует сюда                        ↑ A0–A7, SP адресуют сюда
```

#### 1.2 Машинное слово

Машинное слово — **32 бита (4 байта)**, порядок байт — **big-endian** (старший байт по меньшему адресу), что соответствует оригинальному Motorola 68000. Все адреса — 32-битные беззнаковые целые. Одно машинное слово хранит: один `int`, один `bool`, **один символ строки** (по требованию задания — один символ на слово, несмотря на неэффективность).

#### 1.3 Регистровый файл

Программисту доступны следующие регистры:

```
Регистры данных (D0–D7)  — 8 × 32 бита
┌────┬────┬────┬────┬────┬────┬────┬────┐
│ D0 │ D1 │ D2 │ D3 │ D4 │ D5 │ D6 │ D7 │
└────┴────┴────┴────┴────┴────┴────┴────┘
 арифм./лог. операции, возврат значений

Адресные регистры (A0–A7)  — 8 × 32 бита
┌────┬────┬────┬────┬────┬────┬────┬────┐
│ A0 │ A1 │ A2 │ A3 │ A4 │ A5 │ A6 │ A7 │
└────┴────┴────┴────┴────┴────┴────┴────┘
 указатели на dmem       FP   SP
 A6 = frame pointer (fp), A7 = stack pointer (sp)

Специальные регистры
┌──────────────────────────────────────────────────────┐
│ PC  — Program Counter, адрес в imem                  │
│ SR  — Status Register: N (negative), Z (zero),       │
│       V (overflow), C (carry)                        │
└──────────────────────────────────────────────────────┘
```

**Соглашения компилятора:**

| Регистр | Роль                                              |
|---------|---------------------------------------------------|
| D0      | возвращаемое значение функции; временный          |
| D1–D5   | рабочие регистры (caller-saved через фрейм)       |
| A0      | аргумент — адрес строки/буфера                    |
| A1      | вспомогательный адресный регистр                  |
| A4      | «замороженный» указатель на массив (sort: main)   |
| A5      | адрес IO-порта (временный, не сохраняется)        |
| A6      | frame pointer (сохраняется через link/unlk)       |
| A7      | stack pointer (управляется автоматически)         |


### 2. Режимы адресации

Все режимы адресации применяются исключительно к dmem. Выборка инструкций всегда идёт через PC из imem и не использует эти режимы.

| Режим                                | Синтаксис ASM   | Вычисление адреса              | Применение          |
|--------------------------------------|-----------------|--------------------------------|----------------------------|
| Регистр данных прямой                | `Dn`            | значение регистра              | локальные `int`/`bool`     |
| Регистр адреса прямой                | `An`            | значение регистра              | указатели                  |
| Непосредственный                     | `#imm`          | константа в потоке инструкций  | числовые литералы          |
| Косвенный через регистр              | `(An)`          | `An`                           | доступ по указателю        |
| Косвенный с постинкрементом          | `(An)+`         | `An`, затем `An += 4`          | обход строки вперёд        |
| Косвенный с предекрементом           | `-(An)`         | `An -= 4`, затем `An`          | push на стек               |
| Косвенный со смещением               | `d(An)`         | `An + d`                       | доступ к переменным фрейма |
| Косвенный с индексом и смещением     | `d(An,Xn)`      | `An + Xn + d`                  | индексирование массива     |

### 4. Карта памяти команд (imem)

```
Адрес    Содержимое
──────────────────────────────────────────────────────────────────
0x0000   Начало кода (первая функция в файле)
         Функции располагаются последовательно в порядке
         их определения в исходном тексте.

         (пример — hello_user_name.bin, 400 байт):

         0x0000  print_str        (первая по тексту)
         0x006C  read_line
         0x0108  main

         (пример — sort.bin, 1532 байт):

         0x0000  write_char
         0x0010  read_int
         0x0128  write_int
         0x0218  print_str
         0x0280  bubble_sort
         0x0390  main
──────────────────────────────────────────────────────────────────
```

Прерываний и векторов прерываний в данной реализации нет — ввод/вывод реализован через memory-mapped порты, доступ к которым осуществляется обычными инструкциями `move`.


### 5. Кодирование инструкций

Каждая инструкция начинается с **базового слова** (32 бита) и может содержать от нуля до трёх дополнительных слов, следующих непосредственно за ним в imem. Выборка инструкции явно меняет PC при каждом прочитанном слове — это и есть «смена машинного слова» в потоке команд.

```
Базовое слово (32 бита):
 31      24 23   20 19   16 15   12 11    8  7  6        0
 ┌─────────┬───────┬───────┬───────┬───────┬──┬──────────┐
 │ opcode  │ srcM  │ dstM  │ srcR  │ dstR  │sz│ reserved │
 │  8 бит  │ 4 бит │ 4 бит │ 4 бит │ 4 бит │1 │  7 бит   │
 └─────────┴───────┴───────┴───────┴───────┴──┴──────────┘

srcM/dstM (режим адресации, 4 бита):
  0x0 REG_D    — регистр данных Dn
  0x1 REG_A    — адресный регистр An
  0x2 IMMED    — непосредственный (следующее слово = значение)
  0x3 MEM_IND  — (An)
  0x4 MEM_POST — (An)+
  0x5 MEM_PRE  — -(An)
  0x6 MEM_DISP — d(An)  (следующее слово = смещение d, знаковое)
  0x7 MEM_IDX  — d(An,Xn) (два следующих слова: d, индекс-регистр)
  0xF NONE     — операнд отсутствует

srcR/dstR (номер регистра, 4 бита):
  0–7  → D0–D7
  8–15 → A0–A7

sz (размер операции, 1 бит):
  0 → long (32 бита, шаг адреса = 4)
  1 → byte (8 бит,  шаг адреса = 1)

Дополнительные слова (по 32 бита каждое):
  +4  если srcM == IMMED  → значение непосредственного операнда
  +4  если dstM == IMMED  → (редко; для ветвлений — адрес перехода)
  +4  если srcM или dstM == MEM_DISP → знаковое 32-битное смещение d
  +4  если srcM или dstM == MEM_IDX  → смещение d
  +4  (дополнительно)    → номер индексного регистра Xn
```

**Пример разбора: `LINK A6, -16` (адрес 0, print_str)**

```
Байты в imem: 60 21 0E 00  FF FF FF F0

Базовое слово 0x60210E00:
  opcode   = 0x60 = LINK
  src_mode = 0x2  = IMMED
  dst_mode = 0x1  = REG_A
  src_reg  = 0x0  (не используется для IMMED)
  dst_reg  = 0xE  = 14 → A6
  size     = 0    = long

Extra word 0xFFFFFFF0 = -16 (знаковое) → смещение для link
```

**Пример разбора: `BGE @84` (адрес 44, print_str_loop)**

```
Байты в imem: 55 2F 00 00  00 00 00 54

Базовое слово 0x552F0000:
  opcode   = 0x55 = BGE
  src_mode = 0x2  = IMMED  (цель ветвления — непосредственный адрес)
  dst_mode = 0xF  = NONE

Extra word 0x00000054 = 84 → абсолютный адрес в imem
```


### 6. Хранение литералов

#### 6.1 Целочисленные литералы

**Непосредственная адресация** используется во всех случаях, когда значение фигурирует в исходном тексте как числовая константа. Компилятор помещает его прямо в extra word базового слова инструкции:

```
var x: int = 42;
→  MOVE.l 42, -4(A6)      ; базовое слово + extra word 0x0000002A
```

Целочисленный литерал **никогда не сохраняется в статическую память dmem** — он всегда встроен в поток инструкций imem. Это единственный режим: значение числа кодируется непосредственно следующим словом в imem после базового слова инструкции.

#### 6.2 Строковые литералы

Строковый литерал **всегда сохраняется в статическую секцию dmem** и никогда не встраивается в поток инструкций. Причина: строка занимает произвольное количество слов и не вписывается в один extra word.

Размещение в dmem:

```
Pascal-строка "Hi\n" в dmem (3 символа, 4 слова = 16 байт):

Адрес    Значение    Смысл
base+0   0x00000003  длина (len = 3)
base+4   0x00000048  'H' (ASCII 72)
base+8   0x00000069  'i' (ASCII 105)
base+12  0x0000000A  '\n' (ASCII 10)
```

Порядок строк в секции данных: в порядке появления строковых литералов в исходном тексте программы (сверху вниз). Каждая строка выравнивается на границу слова (4 байта) — это выполняется автоматически, так как каждый символ и сам заголовок длины занимают ровно 4 байта.

Во время выполнения в инструкцию встраивается **адрес** строки (непосредственным операндом), а не её содержимое:

```
print_str("Hello, ");
→  MOVEA.l 0x0050, A0   ; 0x0050 — адрес строки в dmem
→  JSR @<print_str>
```

#### 6.3 Булев литерал

`true` и `false` обрабатываются как целочисленные литералы 1 и 0 соответственно. Хранятся непосредственно в потоке инструкций (imem), в статическую память не помещаются.

### 7. Хранение переменных

#### 7.1 Локальные переменные функции → стек (фрейм)

Все локальные переменные отображаются на **стековый фрейм** в dmem. Регистры D0–D5 используются как временные рабочие значения, но не являются «домом» переменной — при вызове любой функции рабочие регистры сохраняются в фрейм через `MOVE.l Dn, d(A6)`.

Причина выбора стека вместо регистров: CISC-ISA поддерживает операции прямо с памятью (`CMP.l d(A6), D0`), поэтому накладные расходы на доступ к фрейму минимальны, а регистры можно свободно использовать как скратч-пространство без сложного графа распределения.

Структура стекового фрейма (растёт вниз):

```
Адрес       Содержимое
──────────────────────────────────────
SP (до jsr)
SP - 4       адрес возврата (push при jsr)
SP - 8       сохранённый A6 вызывающей стороны (push при link)
             ← A6 (новый frame pointer) указывает сюда
A6 - 4       первая локальная переменная / сохранённый регистр
A6 - 8       вторая локальная переменная
...
A6 - N       N/4-я переменная (N = размер фрейма из link)
             ← SP после link
```

**Пример: функция `bubble_sort` с фреймом на 28 байт**

```
Вызов: SP=0x1E000

  jsr bubble_sort → push(ret_addr): SP=0x1DFFC, mem[0x1DFFC]=ret_addr
  link A6, -28:
    push(old A6):   SP=0x1DFF8, mem[0x1DFF8]=old_A6
    A6 = 0x1DFF8
    SP -= 28:       SP=0x1DFDC

Слоты фрейма (относительно нового A6=0x1DFF8):
  -4(A6)  = 0x1DFF4 : saved D1
  -8(A6)  = 0x1DFF0 : saved D2
  -12(A6) = 0x1DFEC : saved D3
  -16(A6) = 0x1DFE8 : saved D4
  -20(A6) = 0x1DFE4 : saved D5
  -24(A6) = 0x1DFE0 : n-1  (outer limit)
  -28(A6) = 0x1DFDC : inner limit

Возврат: unlk A6 → SP=A6=0x1DFF8, A6=pop()=old_A6, SP=0x1DFFC
         rts       → PC=pop()=ret_addr, SP=0x1E000
```

Если при разработке компилятора понадобится больше локальных переменных, чем умещается — просто увеличивается отрицательное смещение в `link`. Количество переменных не ограничено ничем кроме размера dmem.

#### 7.2 Параметры функции → через регистры и стек

В текущей реализации компилятор передаёт параметры через регистры (простое соглашение вызовов):

- первый `int`/`bool` аргумент → D0
- первый `str` (адрес) аргумент → A0
- дополнительные аргументы → D1, A1, ... (по необходимости)

При стандартном m68k-соглашении (для будущего компилятора) параметры могут передаваться через стек с доступом по `+8(A6)`, `+12(A6)` и т.д. (положительные смещения от frame pointer).

#### 7.3 Глобальных переменных нет

Язык не поддерживает изменяемых глобальных переменных. Только строковые литералы и буферы (которые по смыслу являются глобальными константами) размещаются в статической секции dmem.


### 8. Хранение процедур (функций)

Каждая функция занимает непрерывный блок в imem. Функции располагаются последовательно в порядке их определения в исходном тексте. Между функциями нет выравнивания — следующая функция начинается сразу за последним байтом предыдущей.

Точка входа (`main`) вызывается извне с помощью `jsr @<addr_main>` или прямым указанием start_pc в эмуляторе. По окончании `main` выполняется `halt`.

Вызов функции (механика `jsr`/`rts`):

```
Компилятор генерирует:           Процессор при исполнении:
  MOVEA.l addr_str, A0          A0 ← адрес аргумента
  JSR @addr_func                 push(PC_следующей_инструкции)
                                 PC ← addr_func

Внутри функции:
  LINK A6, -N                   создать фрейм
  ...тело...
  UNLK A6                        уничтожить фрейм
  RTS                            PC ← pop() (возврат)
```


### 9. Хранение прерываний

Прерывания в данной реализации **отсутствуют**. Ввод/вывод реализован через **memory-mapped порты** — специальные адреса в dmem, которые при чтении/записи выполняют IO-операцию:

```
Доступ к порту — обычная инструкция move:

Чтение (read_char):
  MOVEA.l 0xFFFF0000, A5    ; адрес порта ввода → A5
  MOVE.l  (A5), D2            ; D2 = следующий токен ввода

Запись (write_char):
  MOVEA.l 0xFFFF0004, A5    ; адрес порта вывода → A5
  MOVE.l  D0, (A5)            ; отправить D0 в буфер вывода
```

Адрес порта встроен в поток инструкций непосредственным операндом (extra word), регистр A5 используется как временный и не сохраняется.

## Система команд

### 1. Классификация процессора

Архитектура процессора Mova относится к классу **CISC (Complex Instruction Set Computer)**. Основания для классификации:

- инструкции имеют **переменную длину** — от 4 до 16 байт в зависимости от режимов адресации операндов;
- одна инструкция может **одновременно читать из памяти и записывать в память** (например, `move.l #0, -8(A6)` вычисляет эффективный адрес `A6-8` и записывает непосредственную константу прямо в ячейку памяти данных);
- поддерживается богатый набор **режимов адресации**: прямая регистровая, непосредственная, косвенная, с постинкрементом, с предекрементом, со смещением, с индексом и смещением;
- количество тактов на исполнение **пропорционально числу машинных слов** в кодировке инструкции, а не фиксировано;
- наличие специализированных инструкций управления стеком — `link` / `unlk` — которые выполняют несколько связанных действий за одно обращение.

Архитектура вдохновлена **Motorola 68000** — классическим CISC-процессором эпохи 1980-х.


### 2. Особенности процессора

#### 2.1 Типы данных и машинные слова

Машинное слово — **32 бита (4 байта)**, порядок байт — **big-endian**.

| Тип данных | Размер | Представление |
|---|---|---|
| Целое со знаком (`int`) | 32 бит | дополнительный код (two's complement) |
| Логическое (`bool`) | 32 бит | `0` = false, ненулевое = true |
| Символ строки | 32 бит | ASCII-код в 32-битном слове (один символ — одно слово) |
| Адрес | 32 бит | беззнаковое целое |
| Длина Pascal-строки | 32 бит | беззнаковое целое, хранится перед символами |

Операции поддерживают два размера: `.l` (long, 32 бита) — основной рабочий размер, и `.b` (byte, 8 бит) — для работы с младшим байтом регистра. В реализации Mova используется исключительно `.l`.

#### 2.2 Устройство регистров

```
Регистры данных   D0–D7   8 × 32 бита   арифметика, хранение временных значений
Адресные рег-ры   A0–A7   8 × 32 бита   указатели в dmem; A7 = SP, A6 = FP
Program Counter   PC      32 бита       адрес текущей инструкции в imem
Status Register   SR      4 бита        флаги: N Z V C
```

**Флаги Status Register:**

| Флаг | Название | Условие установки |
|------|----------|-------------------|
| N | Negative | результат отрицателен (старший бит = 1) |
| Z | Zero | результат равен нулю |
| V | Overflow | знаковое переполнение |
| C | Carry | беззнаковый перенос или заём |

Флаги устанавливаются большинством арифметических и логических инструкций. Инструкции пересылки (`move`, `movea`) устанавливают только N и Z. Адресные операции (`link`, `unlk`, ветвления) флаги не изменяют.

#### 2.3 Устройство памяти

**Гарвардская архитектура** — два физически разделённых пространства с независимой адресацией:

```
imem (instruction memory)  — только чтение во время исполнения
                              PC всегда указывает в imem

dmem (data memory)          — чтение и запись
                              все адресные регистры A0–A7 указывают в dmem
```

Пространства dmem и imem адресуются с нуля независимо. Адрес `0x0064` в imem и адрес `0x0064` в dmem — разные физические ячейки.

**Карта dmem:**

```
0x00000000  начало статических данных (строки программы)
...         статические Pascal-строки и буферы
0x0001E000  начальное значение SP; стек растёт вниз
...         стековые фреймы функций
0xFFFF0000  порт ввода  (IO_IN)
0xFFFF0004  порт вывода (IO_OUT)
```

#### 2.4 Устройство ввода-вывода

Ввод-вывод реализован через **memory-mapped I/O**: специальные адреса в dmem при обращении к ним не читают/пишут физическую память, а выполняют операцию с потоком токенов.

```
0xFFFF0000 (IO_IN)   — MOVE.l (A5), Dn  → D n получает код следующего входного символа
                        если буфер пуст — возвращает 0xFFFFFFFF (= -1, признак EOF)

0xFFFF0004 (IO_OUT)  — MOVE.l Dn, (A5)  → символ с кодом Dn добавляется в буфер вывода
```

Ввод моделируется как заранее заполненная очередь токенов (символов). Вывод — накапливаемый список. По окончании программы содержимое буфера вывода отображается как результат.

**Прерывания** в реализации отсутствуют — вся работа с внешним миром происходит через polling: программа сама обращается к портам когда нужно.

#### 2.5 Поток управления

Нормальный поток: PC увеличивается на 4 при каждой выборке слова из imem. Поскольку инструкция состоит из нескольких слов, PC к моменту исполнения уже указывает на **следующую** инструкцию.

Изменение потока управления происходит через:

- `jmp @addr` — безусловный переход;
- `jsr @addr` — вызов подпрограммы (push PC, jump);
- `rts` — возврат из подпрограммы (pop PC);
- условные ветвления `beq`, `bne`, `blt`, `bgt`, `ble`, `bge`, `bmi`, `bpl`, `bcc`, `bcs`, `bvc`, `bvs`, `bra` — переход если условие выполнено.

Все адреса переходов — **абсолютные** адреса в imem, хранятся как 32-битное extra-слово.

Стек вызовов располагается в dmem и управляется регистром A7 (SP). Вызов функции: `jsr` декрементирует SP на 4 и сохраняет адрес возврата. `link A6, #-N` дополнительно сохраняет старый A6 и резервирует N байт для локальных переменных. `unlk A6` и `rts` восстанавливают стек в обратном порядке.

### 3. Режимы адресации

| № | Режим | Синтаксис | Код | Вычисление EA | Extra слов |
|---|-------|-----------|-----|---------------|-----------|
| 1 | Регистр данных прямой | `Dn` | 0x0 | значение регистра Dn | 0 |
| 2 | Регистр адреса прямой | `An` | 0x1 | значение регистра An | 0 |
| 3 | Непосредственный | `#value` | 0x2 | константа = следующее слово в imem | 1 |
| 4 | Косвенный | `(An)` | 0x3 | EA = An | 0 |
| 5 | Косвенный с постинкрементом | `(An)+` | 0x4 | EA = An, затем An += шаг | 0 |
| 6 | Косвенный с предекрементом | `-(An)` | 0x5 | An -= шаг, EA = An | 0 |
| 7 | Косвенный со смещением | `d(An)` | 0x6 | EA = An + d | 1 |
| 8 | Косвенный с индексом | `d(An,Xn)` | 0x7 | EA = An + Xn + d | 2 |
| — | Нет операнда | — | 0xF | — | 0 |

Шаг для постинкремента/предекремента: 4 байта для `.l`, 1 байт для `.b`.

Смещение `d` для режимов 7 и 8 — знаковое 32-битное целое, хранится в extra-слове.

### 4. Формат кодирования инструкций

#### 4.1 Структура базового слова

Каждая инструкция начинается с **базового слова** (32 бита), за которым следует от 0 до 3 дополнительных слов (extra words) по 32 бита каждое.

```
Базовое слово:

 31      24 23   20 19   16 15   12 11    8  7   6        0
 ┌─────────┬───────┬───────┬───────┬───────┬───┬──────────┐
 │ opcode  │ srcM  │ dstM  │ srcR  │ dstR  │ sz│ reserved │
 │  8 бит  │ 4 бит │ 4 бит │ 4 бит │ 4 бит │ 1 │  7 бит   │
 └─────────┴───────┴───────┴───────┴───────┴───┴──────────┘

opcode  [31:24] — код операции (см. таблицу опкодов)
srcM    [23:20] — режим адресации источника
dstM    [19:16] — режим адресации приёмника
srcR    [15:12] — регистр источника (0–7: D0–D7, 8–15: A0–A7)
dstR    [11: 8] — регистр приёмника
sz      [   7]  — размер операции: 0 = long (32 бит), 1 = byte (8 бит)
reserved[ 6: 0] — зарезервировано, всегда 0
```

#### 4.2 Дополнительные слова (extra words)

После базового слова следуют extra-слова в строго определённом порядке:

```
Порядок extra-слов:

1. Если srcM == IMMED (0x2):   4 байта — значение непосредственного операнда src
2. Если dstM == IMMED (0x2):   4 байта — значение непосредственного операнда dst
   (для ветвлений/jmp/jsr дополнительно хранит адрес перехода)
3. Если srcM == MEM_DISP (0x6): 4 байта — знаковое 32-бит смещение d для src
4. Если dstM == MEM_DISP (0x6): 4 байта — знаковое 32-бит смещение d для dst
5. Если srcM == MEM_IDX  (0x7): 4 байта — смещение d; 4 байта — номер рег. индекса
6. Если dstM == MEM_IDX  (0x7): 4 байта — смещение d; 4 байта — номер рег. индекса
```

#### 4.3 Таблица размеров инструкций

| Комбинация режимов | Размер (байт) | Число слов |
|---|---|---|
| reg + reg | 4 | 1 |
| (An)+ + reg | 4 | 1 |
| reg + (An) | 4 | 1 |
| reg + (An)+ | 4 | 1 |
| reg + MEM_IND | 4 | 1 |
| только opcode (rts, halt, unlk) | 4 | 1 |
| IMMED + reg | 8 | 2 |
| reg + MEM_DISP | 8 | 2 |
| (An)+ + IMMED (ветвление/jsr) | 8 | 2 |
| LINK (#d, An) | 8 | 2 |
| IMMED + MEM_DISP | 12 | 3 |
| MEM_DISP + reg | 8 | 2 |
| MEM_DISP + MEM_DISP | 12 | 3 |
| MEM_IDX + reg | 12 | 3 |
| IMMED + MEM_IDX | 16 | 4 |

#### 4.4 Разбор конкретного примера

**`move.l #0, -8(A6)` — запись нуля в слот фрейма:**

```
Байты: 01 26 0E 00  00 00 00 00  FF FF FF F8

Базовое слово 0x01260E00:
  [31:24] opcode   = 0x01        → MOVE
  [23:20] srcM     = 0010 = 0x2  → IMMED
  [19:16] dstM     = 0110 = 0x6  → MEM_DISP
  [15:12] srcR     = 0000 = 0    (для IMMED не используется)
  [11: 8] dstR     = 1110 = 14   → A6 (регистр 14 = A0+6 = A6)
  [    7] size     = 0           → long (32 бит)
  [ 6: 0] reserved = 0000000

Слово 1: 0x00000000 → значение источника (src = 0)
Слово 2: 0xFFFFFFF8 → смещение dst (d = -8, знаковое)

Итого: 12 байт, 3 слова → 3 fetch + 1 exec = 4 такта
```

**`bge @84` — условный переход:**

```
Байты: 55 2F 00 00  00 00 00 54

Базовое слово 0x552F0000:
  [31:24] opcode   = 0x55        → BGE
  [23:20] srcM     = 0010 = 0x2  → IMMED (целевой адрес закодирован как imm)
  [19:16] dstM     = 1111 = 0xF  → NONE
  остальные поля  = 0

Слово 1: 0x00000054 = 84 → абсолютный адрес перехода в imem

Итого: 8 байт, 2 слова → 2 fetch + 1 exec = 3 такта
```

**`link A6, #-16` — создание стекового фрейма:**

```
Байты: 60 21 0E 00  FF FF FF F0

Базовое слово 0x60210E00:
  opcode   = 0x60  → LINK
  srcM     = 0x2   → IMMED (смещение = следующее слово)
  dstM     = 0x1   → REG_A
  srcR     = 0x0
  dstR     = 0xE = 14 → A6

Слово 1: 0xFFFFFFF0 = -16 → смещение для SP

Итого: 8 байт → 3 такта
```

#### 5.2 Детальное описание инструкций с тактами

Модель тактов: каждая выборка слова из imem (base word и каждое extra word) занимает **1 такт**. Исполнение занимает ещё **1 такт**. Итого:

```
Тактов = (количество слов в инструкции) + 1
```

#### MOVE — пересылка данных
```
Синтаксис:  move.l <src>, <dst>
Действие:   dst ← src
Флаги:      N, Z устанавливаются по результату; V=0, C=0
```

| Форма | Пример | Байт | Тактов |
|---|---|---|---|
| reg → reg | `move.l D2, D3` | 4 | 2 |
| (An)+ → reg | `move.l (A1)+, D0` | 4 | 2 |
| reg → (An) | `move.l D0, (A1)` | 4 | 2 |
| reg → MEM_DISP | `move.l D1, -4(A6)` | 8 | 3 |
| MEM_DISP → reg | `move.l -4(A6), D1` | 8 | 3 |
| #imm → reg | `move.l #42, D0` | 8 | 3 |
| #imm → MEM_DISP | `move.l #0, -8(A6)` | 12 | 4 |
| (An)+ → (An)+ | `move.l (A0)+, (A1)+` | 4 | 2 |

#### MOVEA — пересылка в адресный регистр
```
Синтаксис:  movea.l <src>, An

Флаги:      не изменяются
```

| Форма | Пример | Байт | Тактов |
|---|---|---|---|
| reg_a → reg_a | `movea.l A0, A1` | 4 | 2 |
| #imm → reg_a | `movea.l #0x1000, A0` | 8 | 3 |
| reg_d → reg_a | `movea.l D0, A1` | 4 | 2 |

```
Синтаксис:  add.l <src>, <dst>
```

| Форма | Пример | Байт | Тактов |
|---|---|---|---|
| reg → reg | `add.l D1, D0` | 4 | 2 |
| #imm → reg | `add.l #1, D2` | 8 | 3 |
| #imm → reg_a | `add.l #4, A1` | 8 | 3 |

#### SUB — вычитание

```
Синтаксис:  sub.l <src>, <dst>

Флаги:      N, Z, V, C
```

| Форма | Пример | Байт | Тактов |
|---|---|---|---|
| reg → reg | `sub.l D0, D3` | 4 | 2 |

#### MUL — умножение
```
Синтаксис:  mul.l <src>, Dn
Действие:   Dn ← Dn × src (знаковое, 32-бит результат)
Флаги:      N, Z
```

| Форма | Пример | Байт | Тактов |
|---|---|---|---|
| #imm → reg | `mul.l #10, D0` | 8 | 3 |

#### DIV — деление
```
Синтаксис:  div.l <src>, Dn

```

| Форма | Пример | Байт | Тактов |
|---|---|---|---|

#### CMP — сравнение
```
Синтаксис:  cmp.l <src>, <dst>
Действие:   временно: dst - src; результат не сохраняется
Флаги:      N, Z, V, C  (устанавливаются по результату вычитания)
```

| Форма | Пример | Байт | Тактов |
|---|---|---|---|
| reg → reg | `cmp.l D3, D1` | 4 | 2 |
| #imm → reg | `cmp.l #32, D1` | 8 | 3 |
| MEM_DISP → reg | `cmp.l -4(A6), D0` | 8 | 3 |
| #imm → MEM_DISP | `cmp.l #0, -4(A6)` | 12 | 4 |

---

#### AND, OR, XOR — логические
```
Синтаксис:  and.l / or.l / xor.l <src>, Dn
Действие:   Dn ← Dn & src  /  Dn | src  /  Dn ^ src
Флаги:      N, Z; V=0, C=0
Размер:     4 байта (reg–reg), 8 байт (imm–reg) → 2–3 такта
```

---

#### NOT — побитовое отрицание
```
Синтаксис:  not.l Dn
Действие:   Dn ← ~Dn
Флаги:      N, Z; V=0, C=0
Размер:     4 байта → 2 такта
```

---

#### ASL, ASR, LSL, LSR — сдвиги
```
Синтаксис:  asl.l / asr.l / lsl.l / lsr.l <cnt>, Dn
Действие:   Dn сдвигается на cnt позиций
            ASR сохраняет знаковый бит; LSR заполняет 0
Флаги:      N, Z
Размер:     8 байт (#imm cnt) → 3 такта; 4 байта (reg cnt) → 2 такта
```

---

#### JMP — безусловный переход
```
Синтаксис:  jmp @addr
Действие:   PC ← addr
Флаги:      не изменяются
Размер:     8 байт → 3 такта
```

---

#### JSR — вызов подпрограммы
```
Синтаксис:  jsr @addr
Действие:   A7 -= 4; mem[A7] ← PC_следующей_инструкции; PC ← addr
Флаги:      не изменяются
Размер:     8 байт → 3 такта
```

---

#### RTS — возврат из подпрограммы
```
Синтаксис:  rts
Действие:   PC ← mem[A7]; A7 += 4
Флаги:      не изменяются
Размер:     4 байта → 2 такта
```

---

#### Условные ветвления BEQ / BNE / BLT / BGT / BLE / BGE / BMI / BPL / BCC / BCS / BVC / BVS / BRA
```
Синтаксис:  bXX @addr
Действие:   если условие истинно: PC ← addr; иначе PC не изменяется
            (PC уже указывает на следующую инструкцию к моменту проверки)
Флаги:      не изменяются

Условия:
  beq: Z=1         bne: Z=0
  blt: N≠V         bgt: Z=0 и N=V
  ble: Z=1 или N≠V bge: N=V
  bmi: N=1         bpl: N=0
  bcc: C=0         bcs: C=1
  bvc: V=0         bvs: V=1
  bra: всегда

Размер:     8 байт → 3 такта (независимо от того, взята ветвь или нет)
```

---

#### LINK — создание стекового фрейма
```
Синтаксис:  link An, #d
Действие:   A7 -= 4; mem[A7] ← An;  (сохранить старый FP)
            An ← A7;                 (новый FP = текущий SP)
            A7 += d                  (d отрицательное: зарезервировать N байт)
Флаги:      не изменяются
Размер:     8 байт → 3 такта
```

Типичное использование: `link A6, #-N` в начале функции, где N = суммарный размер локальных переменных + сохранённых регистров. После `link` локальные переменные доступны по адресам `-4(A6)`, `-8(A6)`, ..., `-N(A6)`.

---

#### UNLK — уничтожение стекового фрейма
```
Синтаксис:  unlk An
Действие:   A7 ← An;           (восстановить SP из FP)
            An ← mem[A7];      (восстановить старый FP)
            A7 += 4
Флаги:      не изменяются
Размер:     4 байта → 2 такта
```

---

#### HALT — остановка
```
Синтаксис:  halt
Действие:   останавливает исполнение; модель фиксирует финальное состояние
Флаги:      не изменяются
Размер:     4 байта → 2 такта
```

|---|---|---|

## 8. Пример полного цикла исполнения одной инструкции

Рассмотрим исполнение `cmp.l #0, -4(A6)` (12 байт, 4 такта):

```
Состояние до: PC=304, A6=0x1DFF8, mem[0x1DFF4]=5

Такт 1 (fetch base word):
  Прочитать imem[304..307] = 0x14206E00
  PC ← 308
  Декодировать: opcode=CMP, srcM=IMMED, dstM=MEM_DISP, dstR=A6

Такт 2 (fetch src extra — значение immediate):
  Прочитать imem[308..311] = 0x00000000  (src = 0)
  PC ← 312

Такт 3 (fetch dst extra — смещение MEM_DISP):
  Прочитать imem[312..315] = 0xFFFFFFFC  (d = -4)
  PC ← 316
  Вычислить EA_dst = A6 + (-4) = 0x1DFF8 - 4 = 0x1DFF4

Такт 4 (execute):
  Прочитать dmem[0x1DFF4] = 5  (значение dst)
  Вычислить: 5 - 0 = 5
  Установить флаги: N=0, Z=0, V=0, C=0
  PC остаётся 316 (следующая инструкция)
```

Выборка инструкции происходит **явно** по словам — каждый переход к следующему слову (PC += 4) это отдельный такт. Именно это является требуемой «явной сменой машинного слова» при выборке инструкции переменной длины.
